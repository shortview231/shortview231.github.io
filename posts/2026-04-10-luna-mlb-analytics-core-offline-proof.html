Building Reproducible MLB Analytics from Structured Data

This project was an exercise in building the full analytical path, not only producing charts: validate input, store it consistently, derive metrics deterministically, test the results, and then present them.

Pipeline

Structured input to normalized SQLite records

The ingestion step checks structured baseball data before persistence, keeps identifiers and fields consistent, and avoids treating repeated input as new data.

Reproducibility

Expected fixtures make the result testable

Known sample inputs provide a baseline for checking team records, player statistics, and derived outputs after code changes.

What the project demonstrates

PythonSQLiteETLSchema validationIdempotencyTestingDerived metricsStreamlit

Proof outputs

The sample run produces standings, player-stat windows, and derived analytical visuals from the same validated data.

Why it matters

The main lesson was that analytical trust comes from the steps around the calculation. Input validation, repeatable storage, deterministic derivation, and test fixtures make a result easier to explain and safer to change later.
